## Limitations and observed verification incident

The first manual attempt intended for localhost used the existing tracked `.env` pointing at the hosted API. It sent only the invented fixture; CORS blocked response visibility, so hosted server outcome is unknown. No user/partner data was used and no hosted success is claimed. Execution was restarted with explicit `VITE_API_URL=http://localhost:8000`, the endpoint is now displayed and `.env.development` defaults to localhost, and the successful local round trip above was independently observed. Browser automation always intercepted backend routes and made no live service requests.

The local backend ran unchanged using already available Python3.14/FastAPI dependencies; its environment was not rebuilt with uv (uv was absent from PATH). This verifies the local HTTP/browser boundary against the pinned backend source, not reproducibility of a backend lock environment. Synthetic report outcomes and target paths still need workstream/domain review. Real contract/auth/account isolation, durable recovery, retention and deployment remain unverified dependencies.
